--------------------------------------------------------------------------------
0. TL;DR — CURRENT STATE IN ONE PARAGRAPH
--------------------------------------------------------------------------------
LTESniffer is a dual-USRP (2x Ettus B210) LTE sniffer that captures BOTH the
downlink (DL, tower->phone) and uplink (UL, phone->tower) of a live LTE cell and
writes MAC-LTE pcap files. As of today it WORKS end-to-end: DL, UL, and RRC
signalling all decode. Getting here required (1) a shared external 10 MHz + 1 PPS
clock feeding both radios (hardware — already installed by the operator), and
(2) FOUR C++ source fixes made today (DCI SNR gate, dual-mode USB buffering, a
re-align abs()->fabs() bug, and an RF-error handler for visibility). The winning
run config is: DL 1825 MHz / UL 1730 MHz, dual mode, 2 RX antennas (-A 2),
clock=external, DCI gate 3.0. DL/RRC/coverage are excellent and stable. UL
decodes but yield is LOW and swings with RF conditions — improving the UL
antenna position is the main remaining lever (a hardware/operator task, not code).
The fixes live in the local dev build only; shipping to the air-gapped appliance
needs a full C++ rebuild + reship.

--------------------------------------------------------------------------------
1. WHAT THE PROGRAM IS
--------------------------------------------------------------------------------
- A FALCON/srsRAN-based passive LTE sniffer. It does NOT transmit. It listens.
- Fork context: repo GuyPeleg123/BOH lineage; local clone at ~/work/LTESniffer.
- Two hardware receivers (USRP B210 software-defined radios):
    * rf_a  = DL radio, serial 32FCD4C  -> tuned to the DL centre freq (-f)
    * rf_b  = UL radio, serial 3367EF9  -> tuned to the UL centre freq (-u)
- Output: MAC-LTE pcap (DLT 147) that Wireshark/tshark can dissect. With a key
  file (-K) it can also decrypt PDCP and write *_decrypted_ip.pcap (DLT 101).
- A web GUI (FastAPI backend + React frontend) wraps the C++ binary: start/stop
  captures, live counters, key derivation, pcap organizing/splitting.

WHY TWO RADIOS + A SHARED CLOCK:
LTE FDD puts DL and UL on different frequencies, so you physically need two
receivers. To decode UL PUSCH the sniffer must know the exact DL<->UL timing
relationship, which means BOTH radios must share ONE sample clock (10 MHz) and
ONE time reference (1 PPS). Two independent clocks (e.g. each B210's own GPSDO)
drift and their PPS edges never align -> UL never decodes. The single most
important hardware fact in this whole project: **UL requires a shared 10 MHz +
1 PPS reference feeding BOTH B210s.** That reference is now installed (external).

3. HOW THE DECODE PIPELINE WORKS (mental model)
--------------------------------------------------------------------------------
Per 1 ms subframe, in LTESniffer_Core.cc main loop (~line 511 onward):
  1. RECEIVE: srsran_ue_sync_zerocopy_multi_usrp() reads one subframe from BOTH
     radios in lockstep (rf_a into buffer_a[], rf_b into buffer_b[]). The two
     UhdStreamThreads stream concurrently; a wrapper compares their PPS
     timestamps and, if they differ, drops dummy samples to RE-ALIGN them
     (Core.cc ~918). With a shared clock the timestamps match, so alignment is
     tiny/zero.
  2. SYNC (ue_sync.c): a state machine. SF_FIND correlates PSS on buffer_a[0]
     (antenna 0 of the DL radio ONLY) to lock subframe timing. Once locked it
     goes SF_TRACK. If antenna-0 samples are corrupt, PSS peak collapses to ~1.0
     and it never leaves FIND -> nothing decodes. (This was the -A 2 bug.)
  3. DL CONTROL (DCISearch.cc): if the DL channel SNR passes a GATE, run the DCI
     blind search on the PDCCH. DCIs are the pointers: a DL grant -> decode
     PDSCH (DL data); a UL grant (DCI format 0) -> schedule a PUSCH decode.
  4. UL DATA (UL_Sniffer_PUSCH.cc via ULSchedule.cc): 4 ms after a UL grant at
     subframe n, decode PUSCH from rf_b's subframe n+4. Chest estimates UL SNR;
     if it clears internal thresholds, the PDU is written and the UL stats row
     printed.
  5. WRITE: decoded MAC PDUs -> pcap (flushed every ~64 writes; short runs look
     empty on disk until the process exits and flushes).

KEY INSIGHT: You cannot get UL without DL. UL grants ride inside DL control
messages. If DL control (DCI) isn't decoding, UL is impossible. So "fix DL
first, then UL" is the correct order, and it is exactly how today went.

4. THE FOUR CODE FIXES MADE TODAY (what/why/where) — CRITICAL SECTION
--------------------------------------------------------------------------------
All are UNCOMMITTED working-tree edits on branch
feat/gui-split-pktindex-and-key-boxes (HEAD a1c5eeb). Confirm with `git diff src/`.

FIX 1 — DCI SNR GATE lowered 6.0 -> 3.0   [src/src/DCISearch.cc ~line 517]
  Code: `if (snr_db > 6.0)` changed to `if (snr_db > 3.0)`.
  Why: The DCI blind search only runs on subframes whose DL channel SNR exceeds
  the gate. Our real-world signal hovers ~5-8 dB and swings; a 6.0 gate threw
  away most subframes (all-or-nothing). One 150 s run at mean SNR 5.76 decoded
  ZERO. Lowering to 3.0 lets marginal subframes attempt decode. SAFE because
  every DCI candidate is still CRC-checked; garbage fails CRC and is dropped.
  IMPACT (the single biggest unlock): DL-SCH 0->6049, UL-SCH 0->20, RNTIs
  37->446, RRC 0->1277 in one 90 s run. This is what turned the project from
  "nothing decodes" to "everything decodes".

FIX 2 — DUAL-MODE USB BUFFERING on the -X/-Z path   [LTESniffer_Core.cc ~line 234]
  Code: added `const std::string tput = ",num_recv_frames=512,recv_frame_size=8000";`
  and appended `tput` to the usrp_a_args / usrp_b_args (-X/-Z) device strings.
  Why: The throughput/buffering args were ONLY added on the -a/auto branch. The
  explicit-serial -X/-Z path (which dual mode uses) opened the B210s with UHD
  DEFAULT buffering. Under the doubled load of -A 2 (2 channels x 2 radios) this
  silently overflowed mid-subframe; the discontinuous IQ corrupted antenna-0's
  buffer -> PSS collapse -> ue_sync stuck in FIND -> 0 DL at -A 2. THIS is the
  real reason 2-antenna mode was "broken"; it was never a bad antenna.
  IMPACT: -A 2 now works — DL 4k-12k, RRC up to 1721, up to 566 UEs, ~27 dB SNR,
  ZERO overflows, stable sync.
  WARNING: Do NOT raise these to 1024/16360. That needs ~33 MB > the kernel
  usbfs default 16 MB budget and fails at device-open with
  `LIBUSB_ERROR_NO_MEM`. 512/8000 (~8 MB) is the safe, proven value. (If you ever
  need more, raise /sys/module/usbcore/parameters/usbfs_memory_mb first.)

FIX 3 — RE-ALIGN abs() -> fabs()   [LTESniffer_Core.cc ~line 921]
  Code: `double diff_time = abs(...)` changed to `fabs(...)`.
  Why: With only <math.h>/<stdlib.h> in scope, abs() is the INTEGER overload, so
  abs(0.0003) == 0. That made diff_time always 0, so the rf_a/rf_b fine re-align
  block below it NEVER ran — a dead no-op. Real UL timing alignment needs it.
  IMPACT: correctness fix for DL/UL sample alignment. Did not regress DL; its
  effect on UL is positive-or-neutral (UL is currently signal-limited, so hard
  to quantify in isolation).

FIX 4 — RF ERROR HANDLER (visibility)   [LTESniffer_Core.cc top ~line 40 + ~line 280]
  Code: added static `lte_rf_error_handler()` + two
  `srsran_rf_register_error_handler(&rf_a/&rf_b, ...)` calls after the opens.
  Why: srsRAN's overflow logger (log_overflow) EARLY-RETURNS if no error handler
  is registered — and none ever was. So "no overflow in the log" was meaningless;
  overflows were physically unreportable. Now they print as
  `[RF A] OVERFLOW (count=N)` (rate-limited). This is what let us diagnose FIX 2.
  IMPACT: pure diagnostics. If -A 2 ever regresses, watch for these lines.

11. DIAGNOSTIC TOOLS (built today; in $CLAUDE_JOB_DIR/tmp — copy into scripts/ if
    you want them permanent). All assume the two serials above.
--------------------------------------------------------------------------------
  specq.py <freq_hz> <serial> <gain> <label>
      Capture IQ (uhd_rx_cfile) and print in-band-vs-noise dB. Tells you if a
      channel is live. Example: python3 specq.py 1825000000 32FCD4C 60 DL

  scan.py <serial> <gain> <f_start_MHz> <f_stop_MHz> <step_MHz>
      Sweep a band and print channel-above-noise per step. USE THIS IF DL STOPS
      DECODING — the carrier may have moved (that is how 1825 was found).
      Example: python3 scan.py 32FCD4C 50 1805 1880 5

  cap.sh <A> <secs> [DL_MHz] [UL_MHz] [extra_flags]
      One clean capture (external clock, gate-3.0 binary) + measure. Prints
      RESULT|A=..|DL-SCH=..|UL-SCH=..|RNTIs=..|RRC=..|meanSNR=..|clean=..
      Handles child-pid SIGINT + flush wait. Example: bash cap.sh 2 90
      NB: for runs >= 90 s, invoke with a Bash timeout >= 300000 ms or the outer
      command can be killed before the pcap flushes.

  MANUAL pcap analysis (Wireshark 3.6.2 / tshark on the target). The MAC-LTE user
  DLT mapping is REQUIRED or frames won't dissect:
    MAC='uat:user_dlts:"User 0 (DLT=147)","mac-lte-framed","0","","0",""'
    sudo -n tshark -r <pcap> -o "$MAC" -Y 'mac-lte.ulsch'   # UL frames
    sudo -n tshark -r <pcap> -o "$MAC" -Y 'mac-lte.dlsch'   # DL frames
    sudo -n tshark -r <pcap> -o "$MAC" -Y 'lte_rrc'         # RRC (note underscore
      for the PROTOCOL filter; FIELDS use hyphen: lte-rrc.*)
  Captures land in ~/ltesniffer-captures/<rundir>/ltesniffer_dual_mode.pcap.

12. CLI FLAG REFERENCE (LTESniffer binary; from ArgManager.cc)
--------------------------------------------------------------------------------
  -f <Hz>   DL centre frequency (rf_a).
  -u <Hz>   UL centre frequency (rf_b). Required for UL/dual.
  -A <n>    Number of RX antennas per radio (1 or 2). Use 2 (fixed today).
  -g <dB>   RX gain (SAME on both radios). Omit for AGC. -1 = AGC.
  -X <args> rf_a (DL) UHD device args, e.g. clock=external,type=b200,serial=32FCD4C
  -Z <args> rf_b (UL) UHD device args, e.g. clock=external,type=b200,serial=3367EF9
            clock= values: internal | gpsdo | external. USE external (shared ref).
  -m <0|1|2> Mode: 0 DL-only, 1 UL-only, 2 DUAL. Use 2. (DL-only -m 0 can segfault
             in this build — known; not needed.)
  -C        Enable cell search (PSS/SSS). Recommended.
  -I <id> -p <prb>   Fixed cell instead of search (use if -C off).
  -r <rnti> Target a single RNTI (0 = all). Handy to force-probe one UE's UL.
  -W <n>    Worker threads (4).
  -S <r> -T <ms>   DCI format split ratio / update interval (0.5 / 100).
  -q <n>    MCS tracking mode (1).
  -z <n>    API mode: -1 off, 0 identity, 1 IMSI, 2 UECapa, 3 all.
  -K <file> Key file -> in-core PDCP decrypt (writes *_decrypted_ip.pcap DLT 101).
  -d        Debug logging (per-subframe PSS/decode lines; used for diagnosis).
  -J <file> JSON event stream for the GUI.
  NOTE: output pcap names are hardcoded by mode (ltesniffer_dual_mode.pcap etc.);
  the GUI separates runs by timestamped subdirectory, not by -F.

13. HARD-WON FACTS / GOTCHAS (do not relearn these)
--------------------------------------------------------------------------------
  * UL needs a SHARED 10 MHz + 1 PPS on BOTH B210s. Two independent GPSDOs do
    NOT align PPS edges -> UL fails. clock=external is that shared reference.
  * DL must decode before UL can (UL grants live inside DL control).
  * Both B210s must be USB3 (lsusb -t shows 5000M). USB2/480M = power starvation
    -> flapping. Keep them on separate USB3 controllers.
  * The DCI SNR gate (DCISearch.cc) is the master throttle. 6.0 was too strict
    for real signals; 3.0 is correct here. CRC still filters garbage.
  * -A 2 depends on the -X/-Z buffering fix. Without it, 2-antenna silently
    overflows and decodes nothing. Do not exceed 512/8000 (usbfs 16 MB limit).
  * pcap flushes every ~64 writes; always SIGINT the ROOT child + wait for
    "Saving MAC PCAP file". Never trust a hard-killed run's frame count.
  * Cell search "finds" cells far below decode SNR (PSS has huge processing
    gain). A found cell at low power/SNR will NOT decode PDSCH — that is normal,
    not a bug. Check meanSNR, not just "found cell".
  * tshark needs the DLT=147 -> mac-lte-framed user-DLT mapping (section 11) or
    frames won't dissect. Protocol filter is lte_rrc (underscore).
  * GUI creds: admin / Sniff2026!  (auth.json; delete it to rotate.)
  * When killing sniffers, match the ROOT binary pattern precisely
    (pgrep -f 'LTESniffer.*serial=32FCD4C'); do NOT pkill broad patterns that
    also match your own shell/grep commands.
